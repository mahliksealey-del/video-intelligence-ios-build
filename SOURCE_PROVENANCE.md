- iPhone 2026-11-20 TikTok acceptance follow-up: browser playback succeeded but the subsequent independent media transfer returned unsupported content. The browser fallback now prioritizes the currently-playing WKWebView video media URL, retains at most five verified HTTPS TikTok-host candidate streams, and retries sequentially only for this browser-selected TikTok route after local AVFoundation validation. Its URLSession is ephemeral and receives only TikTok-domain cookies from that user's own WebKit data store (RFC domain scoping); it never imports cookies for YouTube or Instagram and does not store cookie content in Git, logs, or release artifacts. The actual webpage response status or coarse MIME is surfaced on failure instead of incorrectly categorizing every rejected media request as a generic webpage. This is an unverified device fix; it must pass the next Xcode build and iPhone acceptance test. Design reference: reyi06/snag's native on-device TikTok WebView and in-memory cookie strategy (GPL-3.0); no source copied.

- iPhone 2026-11-20 TikTok primary-route cleanup: actual device success confirmed for visible TikTok browser → Use Video → Download Video → library.
